# N-puzzle

## N-puzzle이란?

N-puzzle은 숫자가 적힌 타일과 하나의 빈 공간으로 이루어진 **슬라이딩 퍼즐(Sliding Puzzle)**이다.

빈 공간과 인접한 타일을 움직여 타일의 위치를 변경할 수 있다.

예를 들어 다음과 같은 `3 × 3` 퍼즐이 있다고 하자.

```text
1 2 3
8   4
7 6 5
```

목표는 간단하다.

> 주어진 초기 상태(Initial State)에서 타일을 이동하여 목표 상태(Goal State)를 만드는 것이다.

`3 × 3` 퍼즐은 숫자 타일 8개와 빈 공간 하나를 가지기 때문에 일반적으로 **8-puzzle**이라고 부른다.

마찬가지로 `4 × 4` 퍼즐은 15개의 숫자 타일을 가지며 **15-puzzle**이라고 부른다.

N-puzzle은 이러한 퍼즐을 특정 크기에 한정하지 않고 일반화한 문제라고 볼 수 있다.

---

## 단순한 퍼즐이 아니라 탐색 문제다

겉으로 보면 N-puzzle은 단순히 숫자를 움직이는 게임처럼 보인다.

하지만 컴퓨터 과학에서 중요한 문제는 타일을 화면에 표시하거나 움직이는 것 자체가 아니다.

핵심은 다음 질문이다.

> **컴퓨터는 초기 상태에서 목표 상태까지 도달하는 이동 순서를 어떻게 찾아낼 수 있을까?**

하나의 퍼즐 상태에서 빈 공간 주변의 타일을 움직이면 새로운 퍼즐 상태가 만들어진다.

```text
현재 상태
    │
    ├── 타일 이동 ──► 새로운 상태 A
    │
    ├── 타일 이동 ──► 새로운 상태 B
    │
    └── 타일 이동 ──► 새로운 상태 C
```

그리고 각각의 새로운 상태에서도 다시 여러 개의 이동이 가능하다.

이를 계속 확장하면 다음과 같은 구조가 만들어진다.

```text
                    초기 상태
                   /        \
                  /          \
              상태 A         상태 B
              /   \          /   \
             /     \        /     \
         상태 C   상태 D  상태 E   상태 F
            .
            .
            .
                       목표 상태
```

즉, N-puzzle은 결국 수많은 상태 중에서 목표 상태까지 이어지는 경로를 찾는 문제가 된다.

이것을 **상태 공간 탐색(State-space Search)** 문제라고 한다.

---

## State란 무엇인가?

**State(상태)**는 특정 순간의 퍼즐 전체 모습을 의미한다.

예를 들어,

```text
2 8 3
1 6 4
7   5
```

이 보드 전체가 하나의 State다.

여기서 숫자 `5`를 빈 공간으로 이동하면:

```text
2 8 3
1 6 4
7 5
```

새로운 State가 만들어진다.

따라서 퍼즐을 해결하는 과정은 다음과 같이 생각할 수 있다.

```text
Initial State
      │
      │ Move
      ▼
    State
      │
      │ Move
      ▼
    State
      │
      ▼
     ...
      │
      ▼
 Goal State
```

결국 N-puzzle을 해결한다는 것은 **Initial State에서 Goal State까지 연결되는 State들의 경로를 찾는 것**이다.

---

## 모든 경우를 확인하면 안 될까?

가장 단순한 방법은 생각할 수 있는 모든 이동을 하나씩 시도하는 것이다.

```text
현재 상태
   ↓
가능한 상태 전부 생성
   ↓
그 상태에서 가능한 상태 전부 생성
   ↓
다시 전부 생성
   ↓
...
```

작은 퍼즐에서는 이런 방식도 동작할 수 있다.

하지만 퍼즐의 크기가 커지면 가능한 상태의 수가 매우 빠르게 증가한다.

그 결과 두 가지 문제가 발생한다.

**Time**

얼마나 많은 상태를 탐색해야 하는가?

**Memory**

탐색하면서 얼마나 많은 상태를 저장해야 하는가?

따라서 단순히 답을 찾는 것만으로는 충분하지 않다.

> **가능한 수많은 상태 중 어떤 상태를 먼저 탐색해야 하는가?**

이것이 이 프로젝트에서 중요한 문제다.

---

## Search Algorithm

State Space에서 Goal State를 찾기 위해 **탐색 알고리즘(Search Algorithm)**을 사용한다.

알고리즘에 따라 State를 탐색하는 방식이 달라진다.

어떤 알고리즘은 가능한 상태를 순서대로 탐색하고, 어떤 알고리즘은 목표에 가까워 보이는 상태를 우선적으로 탐색한다.

N-puzzle에서 중요한 탐색 알고리즘 중 하나가 **A* (A-star)**이다.

A*는 State를 평가할 때 두 가지 정보를 함께 사용한다.

```text
지금까지 사용한 비용
        +
앞으로 필요할 것으로 예상되는 비용
        │
        ▼
예상되는 전체 비용
```

이를 일반적으로 다음과 같이 표현한다.

```text
f(n) = g(n) + h(n)
```

여기서:

* `g(n)` : 현재 State까지 실제로 이동한 비용
* `h(n)` : 현재 State에서 Goal까지 남은 비용의 추정값
* `f(n)` : 해당 State를 거쳐 Goal까지 가는 전체 비용의 추정값

A*가 실제로 State를 어떻게 선택하고 탐색하는지는 **Search Algorithms** 페이지에서 자세히 다룬다.

---

## 아직 풀지도 않았는데 남은 거리를 어떻게 알까?

여기서 문제가 하나 생긴다.

`g(n)`은 이미 이동한 횟수이기 때문에 정확히 알 수 있다.

하지만 `h(n)`은 다르다.

아직 Goal까지 가보지도 않았는데 정확히 몇 번 이동해야 하는지 어떻게 알 수 있을까?

정확한 값을 알 수 없기 때문에 **추정한다.**

이때 사용하는 것이 **Heuristic(휴리스틱)**이다.

대표적인 방법 중 하나가 **Manhattan Distance**다.

예를 들어 어떤 타일이 Goal에서 있어야 할 위치로부터 오른쪽으로 2칸, 아래로 1칸 떨어져 있다면:

```text
2 + 1 = 3
```

처럼 가로와 세로 방향의 거리를 이용하여 Goal까지의 비용을 추정할 수 있다.

즉 Heuristic은 정답을 알려주는 것이 아니라,

> **어떤 State가 Goal에 더 가까워 보이는가?**

를 Search Algorithm이 판단할 수 있도록 도와준다.

Heuristic의 종류와 성질은 **Heuristics** 페이지에서 자세히 다룬다.

---

## 모든 퍼즐이 풀리는 것은 아니다

N-puzzle에서는 숫자가 올바르게 들어 있다고 해서 반드시 Goal State까지 도달할 수 있는 것은 아니다.

예를 들어 두 퍼즐 모두 `1~8`과 빈 공간을 정확히 가지고 있더라도 특정 타일의 배치 관계에 따라 Goal State에 도달할 수 없는 경우가 존재한다.

즉,

```text
Valid Puzzle
```

과

```text
Solvable Puzzle
```

은 서로 다른 개념이다.

파일 형식과 숫자 구성이 올바르더라도 퍼즐 자체가 풀리지 않을 수 있다.

따라서 Solver가 무작정 탐색을 시작하기 전에:

> **이 Initial State에서 Goal State까지 실제로 도달할 수 있는가?**

를 판단하는 과정이 필요하다.

---

## Goal State

우리가 흔히 생각하는 퍼즐의 Goal은 다음과 같은 형태다.

```text
1 2 3
4 5 6
7 8
```

하지만 Goal State는 반드시 이 형태일 필요는 없다.

N-puzzle 프로젝트에서는 중요한 형태로 **Snail Solution**이 등장한다.

숫자가 바깥쪽에서 안쪽으로 달팽이처럼 회전하며 배치되는 방식이다.

`3 × 3`이라면 다음과 같은 형태가 될 수 있다.

```text
1 2 3
8   4
7 6 5
```

따라서 프로그램은 Goal을 단순히 고정된 배열로 생각하는 것이 아니라 **퍼즐 크기에 따라 Goal State를 생성할 수 있어야 한다.**

Goal State는 이후의 여러 과정에 영향을 준다.

```text
Goal State
    │
    ├── 퍼즐 완료 판단
    ├── Heuristic 계산
    ├── Solvability 판단
    └── Search의 최종 목적지
```

## 전체 프로젝트의 흐름

N-puzzle 프로그램 전체를 하나의 흐름으로 보면 다음과 같다.

```text
Puzzle File
     │
     ▼
   Parsing
     │
     ▼
 Validation
     │
     ▼
Initial State
     │
     ├──────────► Solvability Check
     │
     ▼
 Goal State
     │
     ▼
Search Algorithm
     ▲
     │
  Heuristic
     │
     ▼
  Solution
     │
     ▼
Sequence of Moves
```

각 단계는 서로 다른 질문을 해결한다.

**Parsing**

> 사용자가 어떤 퍼즐을 입력했는가?

**Validation**

> 입력된 데이터가 올바른 N-puzzle인가?

**Goal Generation**

> 우리가 도달해야 하는 상태는 무엇인가?

**Solvability**

> 이 퍼즐은 실제로 Goal까지 도달할 수 있는가?

**Search**

> 어떤 이동 순서로 Goal까지 갈 수 있는가?

**Heuristic**

> 어떤 State를 먼저 탐색하는 것이 유리한가?

---

## 이 프로젝트에서 배우는 것

N-puzzle의 목적은 단순히 퍼즐 게임 하나를 만드는 것이 아니다.

이 프로젝트를 통해 다음과 같은 컴퓨터 과학의 핵심 개념을 경험하게 된다.

* State Representation
* State-space Search
* Graph Search
* Search Algorithm
* Heuristic
* A*
* Cost Function
* Solvability
* Time Complexity
* Space Complexity

전체적인 흐름을 한 줄로 정리하면 다음과 같다.

```text
Puzzle
   ↓
State
   ↓
State Space
   ↓
Search Problem
   ↓
Search Algorithm
   ↓
Heuristic
   ↓
Solution
```

즉 N-puzzle을 통해 배우는 핵심 질문은 이것이다.

> **선택 가능한 경우의 수가 매우 많을 때, 컴퓨터는 어떻게 목표까지 가는 경로를 효율적으로 찾아낼 수 있는가?**

이제부터 이 문제를 구성하는 각각의 개념을 하나씩 살펴본다.
